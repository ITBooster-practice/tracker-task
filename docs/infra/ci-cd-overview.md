# CI для команды: быстрый старт

CI проверяет выбранные приложения и показывает результат в GitHub Actions и PR. Workflow находится в [.github/workflows/ci.yml](../../.github/workflows/ci.yml); события запуска, выбор приложений и команды описаны в [обзоре CI/CD](./README.md#когда-и-что-проверяет-ci).

## Как читать статусы

В запуске CI есть три jobs:

- `plan` проверяет правила CI и выбирает приложения по изменениям.
- `checks` выполняет прикладные проверки выбранных приложений; для изменений только в документации он пропускается.
- `CI` формирует итоговый результат, включая допустимый пропуск прикладных проверок.

Зелёный итоговый статус означает, что необходимые проверки прошли. Красный указывает на ошибку планирования или проверок; откройте упавший шаг. Статус `in progress` означает, что результат ещё не готов. Пропуск `checks` сам по себе не является ошибкой: сначала проверьте результат `plan` и итоговый статус `CI`.

Markdown проверяется отдельным workflow. Для PR только с документацией дождитесь и его результата.

Обязательность успешных проверок перед merge определяется правилами репозитория.

## Что делать при падении

1. Откройте упавший job и первый шаг с ошибкой.
2. Найдите причину: lint, типы, unit-тесты и покрытие, e2e или сборка.
3. Повторите команду шага локально из корня репозитория, подготовив указанное в workflow окружение. API e2e требуют тестовой БД и Redis и применяют миграции к тестовой БД.
4. Исправьте ошибку и отправьте обновление в тот же PR.

Если падает `plan`, проверьте правила в `scripts/ci` командой `pnpm test:ci`. Если падает Markdown, запустите `pnpm lint:md`. Состав прикладных проверок и пороги покрытия приведены в [обзоре проверок приложения](./README.md#проверки-выбранного-приложения).

## Как связаны CI и релиз

Публикация образов запускает полный CI обоих приложений для SHA релизного тега. Инструкция находится в [разделе публикации образов](./release-process.md#публикация-релизных-образов-в-ghcr). Автоматический деплой отключён; успешная публикация не означает обновление стенда.
