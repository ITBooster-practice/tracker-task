# Архивация досок проекта

[BoardsService](../../apps/api/src/boards/boards.service.ts) архивирует доску вместе с её колонками и задачами, сохраняя записи в БД. Создание и настройка описаны в [руководстве редактора доски](../frontend/board-settings.md); схемы CRUD находятся в [board.schema.ts](../../packages/types/src/boards/schemas/board.schema.ts), маршруты — в [BoardsController](../../apps/api/src/boards/boards.controller.ts).

## Запрос архивации

`POST /teams/:teamId/projects/:projectId/boards/:boardId/archive` доступен владельцу и администратору команды. Передайте `updatedAt` доски из последнего полученного снимка:

```json
{ "expectedUpdatedAt": "2026-11-03T10:00:00.000Z" }
```

[archiveBoardSchema](../../packages/types/src/boards/schemas/archive-board.schema.ts) задаёт строгий контракт `ArchiveBoard`: обязательная ISO-строка `expectedUpdatedAt`, без дополнительных полей. Успех — `204` без тела; `400` означает некорректное тело, `403` — отсутствие прав, `404` — отсутствующий проект, отсутствующая или архивная доска, `409` — изменение версии доски. После конфликта заново получите её настройки перед повтором.

`Board.archivedAt` — nullable timestamp, в [API Board](../../packages/types/src/boards/types/board.types.ts) — `string | null`. Архивация устанавливает дату и снимает `isDefault`. Доска и её задачи исчезают из активных списков и поиска; чтение по ID возвращает `404`. Создание, изменение, удаление и перенос задач внутри архивной доски недоступны. `DELETE /teams/:teamId/projects/:projectId/boards/:boardId` сохраняет отдельное назначение: удаление пустой неосновной активной доски.

## Основная доска и блокировки

Основную доску можно архивировать: следующей основной становится самая ранняя активная по `createdAt`, затем `id`. Если активных досок не осталось, проект остаётся без основной; первая новая доска становится основной. Выбор колонки при создании задачи описан в [контракте Tasks](./tasks.md#создание-задачи-create).

Транзакция сначала блокирует проект через `FOR NO KEY UPDATE`, затем все активные доски проекта через `FOR UPDATE` в порядке `id`. Блокировка проекта сериализует архивацию и выбор основной доски при создании, сохраняя совместимость с проверками внешних ключей при создании задач и колонок. Сохраняйте этот порядок при расширении архивации и перемещения между досками; операции с задачами повторно проверяют `archivedAt: null` под блокировкой.
