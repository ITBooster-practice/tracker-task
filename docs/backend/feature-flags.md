# Флаги на API

API хранит состояния в БД приложения, защищает операции и уведомляет клиентов об изменениях. Все endpoint-ы требуют cookie-сессию. Управление доступно только [разработчику системы](./system-developer.md), независимо от ролей в командах.

## Хранение и регистрация

`FeatureFlag` содержит `id`, уникальный `key`, `enabled` с default `false` и технический `updatedAt`. `FeatureFlagsRevision` хранит общую версию. Состояние и версия изменяются одной транзакцией. Аудита и метаданных жизненного цикла нет.

Ключи и подключение определяются в [реестре @repo/types](../../packages/types/src/feature-flags/registry.ts). `connectedFeature` вычисляется из реестра. Добавление/подключение/удаление выполняются кодом и SQL-миграциями данных. Runtime-создания и синхронизации при старте нет. [Порядок работы](../work/feature-flags.md).

## Подключение проверок

Добавьте ключ в `FEATURE_KEYS` и название блока в `FEATURE_REGISTRY` вместе с проверками. Условный пример после регистрации `NEW_SECTION`:

```ts
import { Controller } from '@nestjs/common'
import { FEATURE_KEYS } from '@repo/types'
import { Authorization } from '../auth/decorators/authorization.decorator'
import { RequireFeatures } from '../feature-flags/feature.guard'

@Authorization()
@RequireFeatures(FEATURE_KEYS.NEW_SECTION)
@Controller('new-section')
export class NewSectionController {}
```

`@Authorization()` запускает JWT-проверку и `FeatureGuard`. Требования метода и контроллера объединяются: все ключи должны быть включены. Для зависимого блока укажите также ключи зависимостей.

В сервисах вызывайте `FeatureFlagsService.requireEnabled(key)` до защищённого действия, включая обработчики вне HTTP. Guard читает PostgreSQL без локального кэша. Отсутствующий, выключенный или неподключённый ключ даёт `403` с `code: FEATURE_DISABLED` и `key`. Сбой БД не разрешает действие. Проверки членства, ролей и доступа к данным сохраняются.

## Контракт

[Общие Zod-схемы](../../packages/types/src/feature-flags/index.ts) используются также Swagger.

| Endpoint                      | Доступ                      | Назначение                                              |
| ----------------------------- | --------------------------- | ------------------------------------------------------- |
| `GET /feature-flags/snapshot` | Авторизованный пользователь | `key`, `enabled`, `updatedAt`, общая `version`          |
| `GET /feature-flags/access`   | Авторизованный пользователь | `canManage`                                             |
| `GET /feature-flags/events`   | Авторизованный пользователь | SSE-уведомления о версии                                |
| `GET /feature-flags`          | Разработчик системы         | `id`, `key`, `enabled`, `updatedAt`, `connectedFeature` |
| `PATCH /feature-flags/:id`    | Разработчик системы         | Только `enabled` и обязательный `expectedVersion`       |

Создания, удаления, редактирования метаданных, архивации, истории и endpoint-а времени нет. Лишние поля PATCH отклоняются с `422`. Включение неподключённого ключа запрещено; выключение старой неподключённой записи разрешено. Снимок считает неподключённые записи выключенными.

Общая версия сериализует конкурентные записи. Устаревший `expectedVersion` возвращает `409` без изменения состояния и версии. Неизвестный ID даёт `404`, отсутствие сессии — `401`, права управления — `403`.

Снимок имеет ETag и поддерживает `304` через `If-None-Match`. Каждая миграция, меняющая набор или подключение, увеличивает версию. Включайте новый ключ после обновления всех экземпляров API.

## Обновление клиентов

После commit сервис отправляет версию через локальный Subject и Redis Pub/Sub. Каждый API обслуживает SSE своих клиентов. Redis не хранит состояния: пропущенные уведомления восстанавливаются сверкой версии PostgreSQL каждые 5 секунд и при восстановлении соединения.

SSE требует сессию, отправляет heartbeat и закрывается при истечении токена. После переподключения клиент перечитывает snapshot. Proxy должен поддерживать длительное соединение без буферизации.
