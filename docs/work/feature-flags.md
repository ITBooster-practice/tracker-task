# Работа с флагами

Флаг — переключатель для раздела, элемента интерфейса или операции API, к которому разработчик добавил проверку в коде. Значение хранится в PostgreSQL и меняется через панель без пересборки приложения. Создание записи само по себе не добавляет и не подключает поведение в приложении.

## Доступ и панель управления

Откройте **Флаги функций** в меню или `/admin/feature-flags`. Управлять флагами может только аккаунт, указанный в настройке API `SYSTEM_DEVELOPER_USER_ID`. Роли в командах этого права не дают. Если настройка пустая, управление недоступно всем. [Как назначить разработчика системы](../backend/system-developer.md).

В панели доступны создание, редактирование, переключение, поиск, фильтры, история и архивация.

| Состояние                 | Что можно делать                                                                     |
| ------------------------- | ------------------------------------------------------------------------------------ |
| Не подключён к приложению | Редактировать заготовку или архивировать её; включение недоступно                    |
| Подключён, выключен       | Включить флаг; проверки в коде пока не разрешают доступ                              |
| Подключён, включён        | Выключить флаг; доступ определяется проверками флага и обычными правами пользователя |
| Архивирован               | Читать историю; изменение, включение и восстановление недоступны                     |

Подключение определяется записью в реестре кода, а состояние — значением в БД. Это разные свойства. Пока ключ есть в реестре, архивация запрещена.

## Создание и подключение

1. Создайте флаг в панели: технический ключ, название, описание и необязательная плановая дата. Новая запись всегда выключена.
2. В [общем реестре](../../packages/types/src/feature-flags/registry.ts) добавьте ключ в `FEATURE_KEYS` и его понятное название в `FEATURE_REGISTRY`. Это название появится в карточке как «Подключён: …».
3. Добавьте проверки в местах, которыми должен управлять флаг. Для интерфейса используйте `FeatureGate`, `useFeature` или `hasFeature`; для страницы по прямому URL — `requireServerFeature`; для API — `@Authorization()` и `@RequireFeatures(...)`. Подробности и примеры: [frontend](../frontend/feature-flags.md#подключение-проверок), [API](../backend/feature-flags.md#подключение-проверок).
4. Проверьте поведение при включённом, выключенном и отсутствующем ключе, прямой URL и запрос к API, а также обычные права пользователя.
5. Соберите `@repo/types` и выпустите обновление frontend и всех экземпляров API. Обновите старые вкладки и список в панели.
6. Убедитесь, что карточка показывает подключение, затем нажмите **Включить**.

Реестр не ищет проверки в исходниках автоматически. Добавляйте запись вместе с проверками и проверяйте их при ревью. Если флаг ограничивает доступ к операции или данным, скрытия интерфейса недостаточно: нужна проверка API. Флаг, предназначенный только для видимости элемента интерфейса, не ограничивает другие операции.

Зависимости задаются в проверках обоих уровней: API должен требовать все необходимые ключи, а frontend — учитывать те же требования. Запись в реестре сама по себе зависимостей не задаёт.

## Переключение и редактирование

Состояние меняется кнопкой **Включить / Выключить** на карточке. Сохранение названия, описания или даты состояние не меняет. Открытые браузеры получают уведомление сервера и загружают новый снимок флагов.

Если список изменился в другом клиенте, API вернёт конфликт `409`. Обновите список и повторите действие по свежим данным. Ошибка загрузки снимка не разрешает доступ по старому включённому значению.

Технический ключ неизменяемый и уникальный, включая архив. Название можно менять и повторять. Для другого технического ключа создайте новую запись и переведите на неё проверки в коде.

Плановая дата — напоминание разработчику, а не расписание переключения. Новая дата и время не могут быть раньше времени API. Уже сохранённый прошедший срок можно оставить при редактировании других полей или очистить.

**История** открывается после выбранной карточки и показывает последние 100 изменений: время, имя и ID автора, состояния до и после действия. Для системных записей отображается «Система»; при отсутствии имени сохраняется ID.

## Завершение поддержки и архивация

Чтобы готовый блок работал постоянно, оставьте его реализацию и удалите привязку к флагу:

1. Удалите проверки ключа из интерфейса, меню, страниц, API, сервисов и связанных тестов. Удалите старую ветку реализации; авторизацию и права на данные сохраните.
2. Найдите оставшиеся ссылки на ключ в `apps` и `packages`. После очистки проверок удалите запись из `FEATURE_REGISTRY` и константу из `FEATURE_KEYS`.
3. Проверьте и выпустите обновление всех поддерживаемых версий приложения. Обновите старые вкладки и завершите использование старых образов.
4. Архивируйте флаг через панель.

Архивация выключает флаг и запрещает его восстановление. История сохраняется, технический ключ остаётся занят навсегда. Оставшаяся в коде проверка архивированного ключа продолжит запрещать доступ; постоянным блок становится после удаления проверки, а не после архивации.

`REQUIRED_FEATURE_KEYS` вычисляется из реестра и блокирует архивацию зарегистрированных ключей. Проверить отсутствие ссылок в коде нужно самостоятельно. Заготовку, которая никогда не подключалась к коду и реестру, можно архивировать сразу.

## Миграции и развёртывание

Создание, редактирование, переключение и архивация записей через панель/API не требуют миграций. Добавление или удаление проверок требует выпуска кода, но не миграции само по себе. Миграции применяются в обычном процессе развёртывания при изменении структуры БД или разовой подготовке данных для выпуска.

Все экземпляры API должны использовать одну БД, один Redis и одинаковую настройку разработчика. Proxy должен поддерживать длительное SSE-соединение без буферизации. После развёртывания проверьте доступ разработчика, нужные состояния флагов и обновление открытого клиента.

Меняйте значения через панель/API: прямое редактирование таблиц обходит аудит, общую версию и уведомления. При ошибочном выключении обновите список и включите флаг обратно. Архив восстановить нельзя.

Технические подробности: [API и хранение](../backend/feature-flags.md), [frontend](../frontend/feature-flags.md).
