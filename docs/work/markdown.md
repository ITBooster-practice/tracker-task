# Markdown

Все Markdown-документы проекта используют общие правила Prettier и markdownlint-cli2. Проверка запускается локально, в pre-commit для staged-файлов и в GitHub Actions, в том числе для PR только с документацией.

## Команды

```bash
# Проверить форматирование и структуру всех документов
pnpm lint:md

# Отформатировать документы и исправить доступные правила автоматически
pnpm lint:md:fix
```

Если после автоисправления остались ошибки, исправьте их вручную и повторите `pnpm lint:md`. Например, линтер не выбирает за автора правильный уровень заголовка или язык блока кода.

## Правила

- Один заголовок первого уровня в начале документа; остальные разделы используют `##`, `###` и далее без пропуска уровня.
- Заголовки записываются через `#`, маркированные списки — через `-`, нумерованные — последовательными числами.
- Вложенные маркированные списки используют отступ в два пробела.
- Пояснения, списки и блоки кода внутри нумерованного пункта выравниваются по его тексту: три пробела для пункта с маркером `1.`.
- Заголовки, списки, таблицы и блоки кода отделяются пустыми строками.
- Блоки кода используют тройные обратные кавычки и язык: `bash`, `typescript`, `json`, `yaml`, `text` и другие подходящие идентификаторы.
- Внутри блоков кода допускаются табы: форматирование примеров следует правилам их языка.
- Длина строки не ограничена линтером: URL, таблицы и команды могут быть длинными. Переносы и выравнивание таблиц выполняет Prettier.
- HTML ограничен элементами `a`, `br`, `details`, `img`, `kbd`, `p`, `summary` для ссылок, изображений и раскрываемых блоков.
- Технические документы описывают поведение, устройство и эксплуатацию; связи с задачами указываются в PR.

Конфигурация находится в корне проекта: [.markdownlint-cli2.jsonc](../../.markdownlint-cli2.jsonc). Она также поддерживается расширением [markdownlint для VS Code](https://marketplace.visualstudio.com/items?itemName=DavidAnson.vscode-markdownlint).

## Область проверки

Проверяются Markdown-файлы в корне, `apps/`, `packages/`, `docs/`, `infra/` и других каталогах проекта. Учитывается `.gitignore`; зависимости, результаты сборки, сгенерированные файлы, локальные планы и настройки агентов исключены.

Pre-commit запускает Prettier и markdownlint-cli2 только для staged-файлов. CI проверяет все документы.
