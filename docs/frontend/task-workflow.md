# Создание, просмотр и редактирование задач

[features/tasks](../../apps/web/features/tasks/) объединяет создание, просмотр и редактирование задач из списка проекта и доски. `TaskCreateDialog` и `TaskEditDialog` используют одну управляемую форму `TaskForm`, а `TaskDetailsDialog` загружает актуальную задачу и предоставляет действия с ней. Общая оболочка `TaskDialog` и компоненты следуют [дизайн-системе](../design-system/README.md).

## Подключение к странице

Передайте идентификаторы команды и проекта и условно монтируйте `TaskCreateDialog`, когда пользователь открывает создание:

```tsx
'use client'

import { useState } from 'react'

import { Button } from '@repo/ui'

import { TaskCreateDialog } from '@/features/tasks'

export function CreateTaskAction({
	teamId,
	projectId,
}: {
	teamId: string
	projectId: string
}) {
	const [open, setOpen] = useState(false)
	return (
		<>
			<Button onClick={() => setOpen(true)}>Создать задачу</Button>
			{open && (
				<TaskCreateDialog
					teamId={teamId}
					projectId={projectId}
					onClose={() => setOpen(false)}
				/>
			)}
		</>
	)
}
```

Компонент загружает участников команды через `useTeamMemberOptions`. Ошибка загрузки исполнителей имеет отдельную кнопку повтора. `onClose` вызывается при отмене или успешном создании; необязательный `onPendingChange` сообщает родителю о выполняющемся запросе.

Список использует маршрут `teamRoutes.projectTasksNew(teamId, projectId)`. Обёртка [views/tasks/ui/create-task-dialog.tsx](../../apps/web/views/tasks/ui/create-task-dialog.tsx) закрывает перехваченный маршрут через `router.back()`, а прямой — через `router.replace(teamRoutes.projectTasks(...))`.

Для создания на любой доске проекта передайте `columns` с `{ id, key, title }`, необязательный `initialColumnId` и `boardName`. [ProjectBoardPageView](../../apps/web/views/boards/ui/project-board-page-view.tsx) передаёт реальные колонки выбранной доски, включая пользовательские с произвольными `key`. Форма отправляет ID выбранной колонки как `boardColumnId`. Начальная колонка определяется по `initialColumnId`, затем по ключу `TODO` или первой доступной колонке. Системная колонка определяет статус; в пользовательской сохраняется переданный статус, по умолчанию `TODO`. Общая страница задач не передаёт колонку: backend выбирает её на основной активной доске. Правила выбора колонки и позиции — в [контракте создания](../backend/tasks.md#создание-задачи-create).

## Форма и отправка

[TaskForm](../../apps/web/features/tasks/ui/task-form.tsx) содержит название, описание, метки, тип, приоритет, исполнителя, срок и статус либо колонку. Схема формы основана на `updateTaskSchema` и требует `title` и массив `labels`; значения по умолчанию и варианты полей находятся в [model/form.ts](../../apps/web/features/tasks/model/form.ts). Перед созданием адаптер проверяет данные через [createTaskSchema](../../packages/types/src/tasks/schemas/create-task.schema.ts), заменяя пустые описание, исполнителя и срок на `undefined`. Основное действие — «Создать задачу» или «Сохранить изменения» в зависимости от режима.

[TaskLabelPicker](../../apps/web/features/tasks/ui/task-label-picker.tsx) позволяет выбрать несколько меток проекта кнопками, добавить имя по Enter или кнопке «Добавить» и снять выбранную метку. Enter в поле меток не отправляет форму. Компонент показывает до 8 найденных невыбранных имён и задерживает запрос подсказок на 250ms после ввода. [useTaskLabels](../../apps/web/shared/api/use-task-labels.ts) передаёт `AbortSignal` и разделяет кэш по команде, проекту и запросу. Во время следующего поиска сохраняются успешные подсказки только той же команды и проекта, сразу отфильтрованные по текущему вводу. Поиск обозначен `aria-busy` и скрытым `sr-only` статусом внутри поля без дополнительной строки; ввод и добавление метки остаются доступны. Ошибка каталога имеет повтор запроса и не мешает ввести другую метку. Ограничения имён и количества задаёт [контракт меток](../backend/tasks.md#метки-задач-и-каталог-проекта).

Новые метки попадают в каталог только после успешного сохранения задачи; отмена формы не меняет каталог. Метки отображаются в карточке доски, строке списка и просмотре задачи.

В создании и редактировании тип, приоритет, статус или колонка и исполнитель представлены открытыми группами [ChoiceGroup](../design-system/README.md#choicegroup-открытый-выбор-одного-варианта): варианты выбираются одним нажатием или стрелками. Подписи сохраняют нейтральный цвет, иконки передают тон варианта; цветная рамка и галочка отмечают только выбранное значение. Сопоставления типов, приоритетов и статусов с иконками и тонами находятся в [task-choice-options.ts](../../apps/web/features/tasks/ui/task-choice-options.ts).

[TaskAssigneeChoices](../../apps/web/features/tasks/ui/task-assignee-choices.tsx) показывает первых 10 участников и отдельный вариант «Без исполнителя». Если выбранный участник находится дальше, он заменяет десятый вариант и остаётся видимым. Сохранённый исполнитель, отсутствующий в текущем списке, показывается как «Назначенный участник». При количестве вариантов участников больше 10 доступны «Показать всех (N)» и «Свернуть список»; сворачивание не меняет выбор. Основные варианты остаются видимыми, дополнительные раскрываются через вертикальный [Collapsible](../design-system/README.md#collapsible-раскрытие-с-изменением-размера). При закрытии скрываемые варианты сразу блокируются и исключаются из фокуса и доступного дерева.

Срок вводится через общий DateTimePicker с клавиатуры или календаря. «Очистить дату» плавно появляется справа от input, занимая часть его ширины; при очистке поле расширяется обратно и получает фокус. При reduced motion размер меняется без анимации. Очистка даёт `null` в форме: при создании адаптер пропускает срок, при редактировании отправляет `dueDate: null`.

[TaskDialog](../../apps/web/features/tasks/ui/task-dialog.tsx) при ширине от 1280px открывает Dialog, ниже — Sheet справа. Создание и редактирование передают `variant='form'`; просмотр использует вариант `details` по умолчанию. Геометрия обоих вариантов задана в [дизайн-системе](../design-system/README.md#input-и-dialog). До гидратации оболочка не выводится. Одновременно активна одна оболочка; экземпляр формы находится выше неё, поэтому изменение ширины сохраняет введённые значения в открытой форме.

Окна задач используют `useOverlayClose`: передают в `TaskDialog` значения `open`, запрос закрытия через `onClose` и `completeClose` через `onClosed`. Родительский `onClose`, включая смену маршрута, вызывается после завершения exit; общий способ подключения описан в [норме закрытия окон](../design-system/README.md#input-и-dialog).

Для заголовков окна, основного текста, подписей и заголовков групп используйте [типографику окон задач](../design-system/README.md#типографика-окон-задач). Варианты ChoiceGroup и кнопки действий сохраняют собственные текстовые роли.

[useCreateTask](../../apps/web/shared/api/use-tasks.ts) отправляет данные в контексте команды и проекта, затем через `refreshProjectTasks` обновляет кэш списков задач и досок, представлений досок, деталей задач и каталога меток этого проекта. Обновление задачи использует ту же инвалидацию. Синхронный guard предотвращает повторную отправку; во время запроса поля и отмена заблокированы. При ошибке форма показывает сообщение рядом с полями и toast, сохраняет черновик и позволяет отправить его повторно. После успеха компонент показывает уведомление и вызывает `onClose`. При активных фильтрах доски форма предупреждает, что сохранённая задача может быть скрыта; предупреждение не блокирует сохранение.

На доске [usePendingBoardTasks](../../apps/web/views/boards/model/use-pending-board-tasks.ts) читает ожидающие мутации `taskMutationKeys.create` своей команды, проекта и доски. Отдельный `PendingBoardTask` отображается перед сохранёнными задачами целевой колонки как «Локальная задача» со статусом «Сохраняется…», без открытия и перетаскивания. Он учитывается в счётчиках, текущих фильтрах и группировке; общий `matchesProjectBoardFilters` проверяет сохранённые и локальные карточки. Эти данные не записываются в кэш API. При ошибке карточка исчезает, черновик и повтор остаются в диалоге; после успеха она исчезает по завершении обновления данных или раньше, когда `context.createdTaskId` из POST уже найден на доске, исключая дубль.

Чтобы добавить поле, согласуйте его контракт в общих схемах создания и обновления, задайте начальное значение и преобразование PATCH в `model/form.ts`, затем подключите поле в `TaskForm` через `register` или `Controller`. Для другого места создания переиспользуйте `TaskCreateDialog`, сохраняя получение данных и отправку в feature.

## Фильтры и адрес списка

[useTaskFilters](../../apps/web/views/tasks/model/use-task-filters.ts) восстанавливает параметры из URL и передаёт их серверу: `status`, `priority`, `type`, `assigneeId`, `search`, `sortBy`, `sortOrder`, `page`, `limit`. Поиск использует название, короткий код, полный UUID задачи и имена меток. Допустимые поля сортировки: `createdAt`, `priority`, `status`; направления: `asc`, `desc`. По умолчанию список использует `createdAt desc` и 20 записей на странице. Контракт поиска и сортировки описан в [модуле API Tasks](../backend/tasks.md#фильтры-и-сортировка-findall). Доска применяет локальный поиск `q` по названию, короткому коду, полному UUID и меткам загруженных задач.

Доска, список и просмотр показывают код `TT-` с первыми восемью символами UUID в нижнем регистре; используйте общий [formatTaskCode](../../packages/types/src/tasks/task-code.ts). Код служит для отображения и может совпадать у нескольких задач; маршруты и API используют полный UUID. Поиск списка принимает `TT-` с 1–8 шестнадцатеричными символами без учёта регистра и возвращает совпадения по префиксу ID в текущем проекте.

Локальный фильтр доски `overdue=true` и подпись срока в карточке используют [isTaskOverdue(task, now)](../../apps/web/features/tasks/model/is-task-overdue.ts): срок строго раньше текущего времени независимо от статуса и колонки; без срока задача не просрочена. Активный фильтр и подписи карточек обновляются автоматически без перезагрузки. Оформление срока задано в [дизайн-системе](../design-system/README.md#палитра-статусов-и-колонок).

В компонентах получайте `now` через [useServerNow](../../apps/web/shared/hooks/use-server-now.ts) и передавайте его в `isTaskOverdue`. Общий [server-clock.ts](../../apps/web/shared/lib/server-clock.ts) синхронизируется в браузере по HTTP `Date` успешных ответов API; backend открывает заголовок через CORS `exposedHeaders`. После синхронизации время идёт по `performance.now()`, поэтому перевод часов устройства его не меняет; до получения `Date` используется время устройства. Один общий интервал обновляет подписчиков раз в секунду и очищается без них; `focus` и `visibilitychange` также вызывают пересчёт.

Изменение фильтра возвращает первую страницу. Сброс очищает поиск, статус, приоритет, тип, исполнителя, сортировку и страницу; размер страницы и чужие query-параметры сохраняются. Запись параметров через History API сохраняет hash и синхронизируется с `useSearchParams`.

## Просмотр и редактирование

Список и доска открывают один [TaskDetailsDialog](../../apps/web/features/tasks/ui/task-details-dialog.tsx). Он получает `teamId`, `projectId`, `taskId` и `onClose`, загружает задачу через `useTaskDetail`, показывает отдельные состояния загрузки и ошибки с повтором. Необязательные `projectName` и `boardName` передают контекст из родительского списка или доски; без них шапка показывает «Задача проекта». Над названием расположены короткий код с кнопкой копирования и тип задачи с иконкой; кнопка копирует код, а Tooltip показывает полный `task.id`.

На desktop описание расположено слева, свойства — справа; в Sheet свойства следуют под описанием. [TaskDetailsProperties](../../apps/web/features/tasks/ui/task-details-properties.tsx) показывает тип задачи (`task.type`), приоритет, исполнителя, срок, фактическую колонку по `task.boardColumnId` и метки; даты создания и обновления находятся внизу блока. Тип, приоритет и колонка сохраняются сразу отдельными PATCH; выбор колонки отправляет `boardColumnId`. Список включает все системные и пользовательские колонки текущей доски и обновляется через `useTaskBoardColumns` и `useBoardsList`. Во время загрузки колонок и при ошибке их выбор заблокирован; доступно действие «Обновить колонки». Шапка и нижние действия остаются на месте при прокрутке тела; размеры и типографика заданы в [геометрии TaskDialog](../design-system/README.md#input-и-dialog) и [ролях окон задач](../design-system/README.md#типографика-окон-задач).

Внизу находятся «Закрыть», доступное по правам редактирование через `TaskEditDialog` и удаление. Подтверждение удаления заменяет действия в footer этого же окна; тело задачи остаётся видимым. Обе панели плавно раскрываются и сворачиваются по высоте с fade по [правилам Collapsible](../design-system/README.md#collapsible-раскрытие-с-изменением-размера); при reduced motion анимация отключена, скрываемые действия сразу недоступны для взаимодействия и скринридера. Подтверждение показывает короткий код, название задачи и переданное `boardName`; без названия доски контекст указывает проект. При открытии фокус переходит на «Отмена»; отмена возвращает обычные действия и фокус на кнопку удаления. Ошибка остаётся в зоне подтверждения и позволяет повторить запрос. После закрытия окна фокус возвращается к элементу, открывшему задачу.

Редактирование доступно создателю задачи, администратору и владельцу команды; удаление — только администратору и владельцу. API повторно проверяет права и принадлежность проекта команде. Во время изменений повторная отправка и закрытие блокируются; ошибка отображается в диалоге и toast и позволяет повторить действие.

В `TaskEditDialog` поле «Колонка» показывает все системные и пользовательские колонки текущей доски задачи. [useTaskBoardColumns](../../apps/web/features/tasks/model/use-task-board-columns.ts) загружает их через `useBoardsList`, находя доску по актуальному `task.boardColumnId`. Обновление списка добавляет новые колонки без сброса черновика. Пока колонки загружаются, при ошибке или исчезновении выбранной колонки сохранение недоступно; повтор загрузки — «Обновить колонки». Отдельного поля статуса в форме редактирования нет.

[useTaskDialogRoute](../../apps/web/features/tasks/model/use-task-dialog-route.ts) открывает задачу параметром `?taskId=UUID` на адресе списка или доски. Например, к существующему URL доски можно добавить `&taskId=UUID`, сохранив `boardId` и фильтры. Открытие использует `history.pushState`, закрытие — `history.replaceState` с удалением только `taskId`; остальные параметры и hash сохраняются. При смене доски прежний `taskId` удаляется.

`taskEditDefaults` сохраняет фактический `boardColumnId` в форме; `taskUpdateData` сравнивает её с исходной задачей и отправляет изменённый ID колонки вместе с остальными изменёнными полями одним PATCH, без `status`. Метки сравниваются как множества без учёта регистра: перестановка не создаёт изменение; снятие всех меток отправляет `labels: []`. Очистка исполнителя или срока передаётся как `null`. Если календарный день срока не изменён, исходное время даты сохраняется. Пустой PATCH не отправляется. Правила переноса, статуса и проверки версии описаны в [контракте PATCH](../backend/tasks.md#обновление-задачи).

## Пустой список и повторная загрузка

[ProjectTasksPageView](../../apps/web/views/tasks/ui/project-tasks-page-view.tsx) различает пустой проект и отсутствие результатов поиска или фильтрации. В первом случае действие «Создать первую задачу» открывает тот же маршрут создания. Во втором сброс фильтров возвращает первую страницу и фокус в поле поиска.

Загрузка и ошибка API обрабатываются отдельно от пустого результата; при ошибке доступен повтор запроса. Под `PageHeader` пустое состояние использует `headingLevel='h2'`.

При первой загрузке доски [BoardLoading](../../apps/web/views/boards/ui/board-loading.tsx) сохраняет шапку, навигацию и рабочий `BoardToolbar`: фильтры и группировка продолжают записываться в URL, действия с доской заблокированы. Серверная [страница доски](<../../apps/web/app/(dashboard)/teams/[id]/projects/[projectId]/board/page.tsx>) заранее загружает список досок с колонками через `boardsService.getAll` под ключом `boardsKeys.list(teamId, projectId)` в отдельный для запроса `QueryClient` и передаёт кэш через `HydrationBoundary`. При полной перезагрузке реальные названия, цвета и число колонок доступны сразу; скелетон заменяет содержимое карточек. Если метаданные недоступны при независимом клиентском монтировании или ошибке серверного запроса, остаются пять колонок без названий. Размеры и оформление заданы в [дизайн-системе состояний](../design-system/README.md#загрузка-пустой-результат-и-ошибка).

При повторном запросе прежние `BoardView` и карточки остаются видимыми: шапка показывает «· обновление», toolbar — «Обновляем · пока показаны предыдущие данные». Временная ошибка повторного запроса оставляет карточки и показывает inline alert с действием «Повторить»; при `401`, `403` или `404`, как и при первичной ошибке без данных, вместо карточек отображается ошибка доски через `EmptyState`.
