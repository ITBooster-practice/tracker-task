# Runtime feature flags на frontend

Снимок загружается через существующий Axios-клиент с cookie-сессией и refresh-flow. `@repo/types` содержит общие схемы; клиент проверяет ответы API. ETag позволяет использовать прежний снимок при 304.

`FeatureFlagsProvider` хранит снимок и статус в TanStack Query и предоставляет React-контекст. `useFeature(key)` и `hasFeature(snapshot, key)` учитывают зависимости: tasks требует projects; boards требует projects и tasks. Отсутствующий ключ закрыт. Контекст не хранится в localStorage и не разделяет пользователей через серверный singleton.

Provider получает уведомления SSE с HttpOnly cookie, без токенов в URL. При новом номере версии он отменяет устаревшую загрузку и повторно запрашивает данные, а также обновляет список/аудит панели. Повторные и старые версии не вызывают лишний запрос. После разрыва соединения или истечения JWT повторное подключение сначала проходит существующий API refresh-flow; retry с задержкой 1–30 секунд. При размонтировании соединение и таймер закрываются.

`FeatureGate` показывает нейтральную загрузку, ошибку с повтором или недоступность раздела. После ошибки refresh даже старый включённый снимок не разрешает отображение функции.

Для разработки без API можно явно задать `NEXT_PUBLIC_FEATURE_FLAGS_DEV_FALLBACK=true` при `NODE_ENV=development`: показываются четыре начальных раздела с предупреждением о локальном режиме. В production, включая stage, этот fallback недоступен. Он не предоставляет права разработчика и не обходит защиту API.

В Docker серверные Axios-запросы используют `API_INTERNAL_URL=http://api:3000`, заданный окружением web-контейнера. HttpOnly cookies передаются API; JWT и guards продолжают работать. Браузер использует прежний публичный NEXT_PUBLIC_API_URL через proxy. Внутренний URL не публикуется в bundle и не проходит внешнюю Basic Auth stage. Без настройки используется публичный URL (обычная локальная разработка).

Серверные layouts проектов и задач, страницы boards/settings и перехваченная модальная страница создания задачи проверяют актуальный снимок с cookie-сессией. Закрытый раздел возвращает 404 при прямом открытии URL. React FeatureGate дополнительно закрывает уже открытый раздел после уведомления. Кэш React ограничен одним серверным render-запросом. Меню и выбор проекта используют тот же runtime-снимок; ссылка `/admin/feature-flags` видна только разработчику системы.

Панель разработчика: `/admin/feature-flags`, серверная проверка доступа и проверка API. Здесь доступны поиск, фильтры активных/включённых/выключенных/архивных флагов, создание, редактирование, переключение, подтверждение архивации и история последних 100 изменений. Key неизменяемый, title можно повторять. Плановая дата — напоминание, автоматического переключения нет. Автор берётся сервером из сессии. Флаги из REQUIRED_FEATURE_KEYS нельзя архивировать. Изменения не применяются оптимистически: UI ждёт подтверждения API; при 409 обновляет список и предлагает открыть форму заново, при 403 закрывает управление.

В форме «Функция включена» задаёт начальное состояние нового флага или изменяет состояние существующего после сохранения; это то же поле enabled, которое переключают кнопки в списке. Новый флаг по умолчанию выключен. Пояснение для встроенных ключей называет конкретный раздел: projects — «Проекты», tasks — «Задачи», boards — «Доски», team-settings — «Настройки команды». Включение флага сохраняет требования других флагов и права на данные. Для нового ключа пояснение указывает: доступ изменится только к функции, для которой добавлены проверки этого ключа в frontend и API. Создание записи не связывает её с кодом автоматически.

Checkbox и общий `DateTimePicker` берутся из shadcn UI-kit `@repo/ui`. Календарь содержит селекты месяца и года; дату можно ввести с клавиатуры. Время задаётся через поле ЧЧ:ММ или Popover с shadcn Select часов/минут, без стандартного time-picker браузера. Иконки имеют курсор pointer. Компонент можно использовать без времени (`withTime=false`), с другими подписями, границами и источником текущей даты. Примеры и параметры: [UI-kit](../../packages/ui/README.md), Storybook `Shared/UI/DateTimePicker` и `Shared/UI/TimePicker`.

Минимум берётся из `GET /feature-flags/server-time`, обновляется раз в минуту, а между ответами продвигается через `performance.now()`. Изменение часов компьютера не меняет этот минимум. До получения времени API и при ошибке его обновления выбор новой даты заблокирован; доступен повтор запроса. Прошедшие дни, часы и минуты недоступны; для сегодняшнего дня время округляется вверх до следующей допустимой минуты. Форма повторно проверяет изменённый срок при сохранении, API выполняет окончательную проверку и возвращает 422 с пояснением, если срок успел пройти.

Значение отображается в часовом поясе браузера и отправляется в ISO UTC. При сохранении неизменённой даты исходный ISO сохраняется вместе с секундами и миллисекундами, поэтому уже прошедший срок не мешает менять название, описание и состояние флага. Дату можно убрать. Она остаётся напоминанием и не переключает функцию автоматически.

Проверки backend и жизненный цикл: [feature flags](../backend/feature-flags.md).
