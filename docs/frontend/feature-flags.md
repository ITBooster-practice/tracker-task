# Флаги на frontend

Флаги приходят из API во время работы приложения. Состояния не вшиваются в сборку и меняются в `/admin/feature-flags`. Ключи и подключение определяются кодом и миграциями: [порядок работы](../work/feature-flags.md).

## Проверки

`FeatureFlagsProvider` загружает snapshot и право управления, подписывается на SSE и обновляет React Query при изменении версии. После переподключения перечитывается снимок. Версия и ETag используются как технические данные.

Проверяйте функции через `hasFeature`, `useFeatureFlags` и `FeatureGate`. Задачи требуют проектов; доски — проектов и задач. Серверные страницы используют `shared/lib/feature-flags/server.ts` и передают cookie-сессию API.

Отсутствующий или выключенный ключ закрывает блок. Ошибка загрузки не включает функции; интерфейс предлагает повторить загрузку. При ответе API `FEATURE_DISABLED` перечитывается snapshot. Проверки frontend дополняют guards API и не заменяют авторизацию.

Явный локальный режим `NEXT_PUBLIC_FEATURE_FLAGS_DEV_FALLBACK=true` действует только при `NODE_ENV=development`: при ошибке API включает известные функции и показывает уведомление. В production fallback не действует.

## Панель разработчика

Панель показывает название из реестра (либо ключ), технический ключ, подключение и состояние. Есть поиск и фильтр включённых/выключенных; список обновляется автоматически. Повторная загрузка доступна при ошибке. Единственная операция изменения — включить/выключить существующий флаг.

Неподключённый выключенный флаг включить нельзя. Старое включённое состояние неподключённой записи можно выключить. Создания, редактирования, описаний, авторов, сроков, архива и истории нет.

PATCH отправляет `enabled` и `expectedVersion` загруженного списка. Во время записи и обновления списка переключатели недоступны. После успеха обновляются список и snapshot; при `409` перечитывается список, при `403` сбрасывается право управления. Панель доступна только [разработчику системы](../backend/system-developer.md).

## Общие UI-компоненты

Календарь, выбор даты/времени, тултипы, popover, диалоги и утилиты даты остаются в `packages/ui` вместе с историями Storybook. Их можно использовать на других страницах. Специфичные для флагов форма, автор, срок, история и запрос серверного времени удалены. Общий `DateTimePicker` продолжает принимать внешний `referenceDate`/`minValue`.
