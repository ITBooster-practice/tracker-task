# Создание и настройка доски

Редактор доски меняет название, описание, колонки и их порядок одной формой. Создание и настройка используют [BoardEditorDialog](../../apps/web/views/boards/ui/board-editor-dialog.tsx); локальные операции над колонками находятся в [model/board-editor.ts](../../apps/web/views/boards/model/board-editor.ts). Изменения применяются общей кнопкой внизу окна.

Размеры, типографика, темы и состояния композиции заданы в [дизайн-системе: редактор доски](../design-system/README.md#редактор-доски). Используйте общие Dialog, Sheet, Input, Button и ChoiceGroup из `@repo/ui`.

## Подключение редактора

Передайте `teamId`, `projectId` и `onClose`. Для настройки передайте полный `BoardView` в `view`; без него редактор создаёт доску с начальными колонками. `projectName` добавляет контекст в шапку, `selectedColumnId` выделяет колонку при открытии из её меню. После успеха `onSaved` получает `BoardListItem`, затем окно закрывается и возвращает фокус инициатору.

```tsx
<BoardEditorDialog
	teamId={teamId}
	projectId={projectId}
	projectName={project.name}
	view={boardView}
	onClose={() => setEditorOpen(false)}
	onSaved={(board) => setSelectedBoardId(board.id)}
/>
```

Управлять доской могут владелец и администратор команды; backend проверяет доступ независимо от интерфейса. Во время сохранения контролы и закрытие блокируются. Отмена закрывает форму без записи. Ошибка запроса оставляет черновик открытым; при конфликте `409` пользователь должен заново открыть настройки с актуальными данными.

## Изменение колонок в черновике

[ColumnDraftRow](../../apps/web/views/boards/ui/board-column-draft-row.tsx) показывает название, счётчик задач и действия. В целевой колонке исходный счётчик и зелёная ожидаемая прибавка отображаются отдельно: «4 задачи + ещё 4», для исходно пустой — «+ ещё 4 задачи»; без переноса обычная пустая колонка показывает «0 задач». Прибавка учитывает цепочки переносов и отмену; задачи переносятся только при общем сохранении. `ColumnDraftPreview` повторяет эти счётчики. Перетаскивание начинается только за grip: мышью, касанием или клавиатурой. Пробел захватывает колонку, стрелки меняют позицию, Пробел или Enter завершают перемещение, Escape отменяет его. `DragOverlay` содержит только презентационный `ColumnDraftPreview`, без повторных интерактивных контролов.

Переименование открывает поле в строке. Enter, потеря фокуса или галочка завершают ввод с обрезкой пробелов; пустое название остаётся ошибкой. Escape возвращает название на момент начала редактирования. [ColumnColorPicker](../../apps/web/views/boards/ui/board-column-color-picker.tsx) меняет цвет в том же черновике.

«Добавить колонку» создаёт `newColumn()` с `isNew: true`, пустым названием и серым цветом. Расширенная строка показывает поля названия и цвета, отметку «Не сохранена» и отмену добавления. Её можно сразу перемещать. Начальные колонки при создании доски используют обычные строки без `isNew`.

На доске должно оставаться от 1 до 50 активных колонок. Названия обязательны, не длиннее 100 символов и уникальны; ключи и переданные ID также уникальны. Название доски ограничено 100 символами, описание — 2000. Контракт проверяет [общая схема доски](../../packages/types/src/boards/schemas/board.schema.ts).

## Удаление и отмена

Системную или последнюю активную колонку удалить нельзя. Если в колонке есть задачи, [ColumnRemovalConfirmation](../../apps/web/views/boards/ui/board-column-removal.tsx) раскрывается под строкой и предлагает другие активные колонки через ChoiceGroup. Учитываются все задачи, включая скрытые фильтрами и ожидающие переноса из других колонок. Пока цель не выбрана, «Удалить при сохранении» недоступно. Открытое подтверждение также блокирует общую кнопку сохранения, сортировку и добавление колонок.

После подтверждения строку заменяет сводка «будет удалена»: количество переносимых задач, цель, её итоговый счётчик и «Отменить удаление». Пустая колонка переходит в это состояние сразу. До общего сохранения задачи и колонки на сервере не меняются.

Модель хранит исходный `taskCount` и все удаляемые строки в массиве `ColumnDraft[]`. `removedTo` связывает источник с целью, `columnDraftTaskCount` вычисляет счётчики, а `columnDraftDestination` находит оставшуюся колонку по цепочке. Не прибавляйте задачи к исходным счётчикам вручную: это нарушит отмену переноса.

```typescript
const withRemoval = removeColumnDraft(columns, source.localId, target.key)
const targetCount = columnDraftTaskCount(withRemoval, target.key)
const restored = restoreColumnDraft(withRemoval, source.localId)
```

`restoreColumnDraft` убирает `removedTo` и защиту пустой колонки, сохраняя переименование и цвет. Например, при `A → B → C` запрос отправляет `A → C` и `B → C`; отмена удаления B возвращает `A → B`. Сумма задач активных колонок сохраняется.

Отмена добавления новой колонки удаляет её из массива. Если она уже стала целью ожидающего переноса задач, пользователь сначала выбирает замену; модель перенаправляет входящие ссылки. Несохранённая колонка не попадает в список удалений API.

## Сохранение и защита от конфликтов

Настройка отправляет один `PATCH /teams/:teamId/projects/:projectId/boards/:boardId` через `useUpdateBoard`. Редактор явно собирает данные запроса:

| Поле                  | Содержимое                                                                               |
| --------------------- | ---------------------------------------------------------------------------------------- |
| `name`, `description` | Итоговые значения формы                                                                  |
| `columns`             | Только активные колонки в итоговом порядке: `id?`, `key`, `title`, `color`               |
| `removedColumns`      | Только сохранённые колонки: `id`, конечный `targetKey`, при необходимости `requireEmpty` |
| `expectedUpdatedAt`   | Версия доски при открытии формы                                                          |
| `columnSnapshot`      | Исходные `id` и `updatedAt` всех колонок                                                 |

`localId`, `isNew`, `removedTo`, `isSystem` и `taskCount` остаются внутри frontend. Снимок берётся при открытии формы и не заменяется фоновым обновлением данных.

[saveBoardSettings](../../apps/api/src/boards/board-settings.ts) под блокировкой доски проверяет снимок, сохраняет форму и переносит задачи в одной транзакции. Для автоматического удаления пустой колонки редактор передаёт `requireEmpty: true`: backend повторно считает задачи этой колонки в проекте. Если задачи появились, он возвращает `409` и откатывает всю операцию. При явном выборе цели перенос выполняется без этой проверки пустоты.

При расширении редактора меняйте переходы состояния в `model/board-editor.ts`, отображение — в соответствующем компоненте строки, палитры или удаления. Новое сохраняемое поле добавляйте в общую схему и backend, затем в явную сборку запроса в `BoardEditorDialog`; локальные поля модели не передавайте через spread всего `ColumnDraft`.

## Архивация доски

В настройках существующей доски владелец и администратор видят «Архивировать доску» слева в footer. [ArchiveBoardDialog](../../apps/web/views/boards/ui/archive-board-dialog.tsx) заменяет содержимое того же Dialog или Sheet и показывает название, число колонок и задач из сохранённого `view`. Пустая и непустая доски имеют отдельные пояснения; доска, колонки и задачи сохраняются в БД, но исчезают из активных списков. Несохранённые изменения редактора не применяются. «Отмена», крестик и Escape возвращают черновик настроек; во время запроса повтор и закрытие заблокированы.

[useArchiveBoard](../../apps/web/shared/api/use-boards.ts) отправляет `expectedUpdatedAt` сохранённого снимка по [контракту архивации](../backend/boards.md#запрос-архивации). Ошибка остаётся в подтверждении; при `409` нужно заново открыть настройки. После успеха мутация ожидает `onArchived`: редактор через `useOverlayClose` завершает exit, затем страница переходит на доску проекта без `boardId` и `taskId`. Только после этого мутация удаляет архивную доску и детали задач из кэша, обновляет списки задач, досок и меток. Обработчик размонтированного редактора не меняет контекст нового проекта. Общий порядок закрытия — в [дизайн-системе](../design-system/README.md#input-и-dialog).
