# Дизайн-система Tracker Task

Дизайн-система задаёт общий визуальный язык трекера IT-проектов: пользователь должен быстро понимать, где находится, что видит и какое действие доступно. Она помогает разработчику собирать согласованные экраны из общего UI, сохраняя плотность рабочего интерфейса и читаемость.

Основа реализации — Tailwind CSS 4 и пакет `@repo/ui` на shadcn/ui и Radix. Правила ниже применяются при создании и изменении интерфейса; наличие старого экрана с другим оформлением не делает его образцом.

## Обязательные правила и исключения

Для новых и изменяемых рабочих экранов используйте роли, токены и размеры из таблиц ниже. Это норма для изменений, а не утверждение, что каждый существующий экран уже ей соответствует. Приоритеты продукта: контекст, читаемые данные, предсказуемые действия.

- Не вводите локальные цвета, шрифты и произвольные размеры при наличии подходящей роли. Плотность данных меняйте композицией и контейнером, а не уменьшением H1.
- Используйте готовые варианты `@repo/ui`. Особая геометрия допустима в доменной композиции только при явной потребности, которую не покрывает общий вариант; она не разрешает обходить типографическую шкалу. Новая общая норма требует изменения этой спецификации.
- Для новой общей нормы измените источник токена или компонента, его story и эту таблицу вместе. Цветовую роль определяйте в обеих темах и `@theme inline`.
- Публичная промостраница может иметь отдельную композицию. Она не задаёт размеры заголовков и контролов рабочего интерфейса.

## Типографика и заголовки

Основа — `--font-sans` установленного Tailwind (`packages/ui/node_modules/tailwindcss/theme.css`), применённый через Preflight. В `RootLayout` отдельный шрифт не подключён:

```css
font-family:
	ui-sans-serif, system-ui, sans-serif, 'Apple Color Emoji', 'Segoe UI Emoji',
	'Segoe UI Symbol', 'Noto Color Emoji';
```

База основного текста — 16/24px, вес 400. Размерная сетка шрифта — `16 + 2n` px, где `n` — целое число: только чётные значения. Таблица фиксирует выбранные роли этой сетки: 12, 14, 16, 18, 20, 24 и 34px. Новый чётный размер требует своей роли в этой спецификации; нечётные 13, 15, 17px и другие в новых и изменяемых UI не допускаются. Заголовки крупнее 16px, описания и вспомогательный текст — 14px, метаданные — 12px. Не уменьшайте основной текст до 14px ради размещения большего объёма данных. Шаг 2px относится к font-size, а не к tracking или отступам.

В таблицах px рассчитаны при корневых 16px; rem масштабируются с пользовательскими настройками. Для фиксированных `text-[34px]` rem дан как эквивалент, сам класс остаётся в px. Базовое межстрочие Preflight — `1.5`. Для новых текстовых ролей выбирайте чётное межстрочие из таблицы; не вводите дробное значение локально. `tracking-tight` = −0.025em, для H1 это −0.85px.

| Роль и применение                                  | Размер px / rem | Межстрочие px | Вес | Tracking | Классы текста и цвета                                                                 |
| -------------------------------------------------- | --------------- | ------------- | --- | -------- | ------------------------------------------------------------------------------------- |
| H1 рабочей страницы, только `PageHeader`           | 34 / 2.125      | 34            | 600 | −0.025em | `text-[34px] leading-[1] font-semibold tracking-tight text-foreground`                |
| Описание страницы                                  | 14 / 0.875      | 20            | 400 | normal   | `text-sm font-normal text-muted-foreground`; `mt-1.5` = 6px                           |
| Заголовок самостоятельной секции                   | 20 / 1.25       | 28            | 600 | normal   | `text-xl font-semibold text-foreground`                                               |
| Заголовок вложенного блока                         | 18 / 1.125      | 28            | 600 | normal   | `text-lg font-semibold text-foreground`                                               |
| `DialogTitle`                                      | 18 / 1.125      | 18            | 600 | normal   | `text-lg leading-none font-semibold`; наследует foreground диалога                    |
| `CardTitle` при наследовании стандартной базы 16px | 16 / 1          | 16            | 600 | normal   | `leading-none font-semibold`; размер не задан примитивом, цвет `text-card-foreground` |
| Развёрнутый текст, узкий `Input`                   | 16 / 1          | 24            | 400 | normal   | `text-base font-normal text-foreground`                                               |

| `Label` поля                                       | 14 / 0.875      | 14            | 500 | normal   | `text-sm leading-none font-medium`; наследует foreground поверхности                  |
| `Button`, кроме `xs`                               | 14 / 0.875      | 20            | 500 | normal   | `text-sm font-medium`; цвет варианта кнопки                                           |
| `Button size='xs'`                                 | 12 / 0.75       | 16            | 500 | normal   | `text-xs font-medium`; цвет варианта кнопки                                           |
| Метаданные и компактные подписи                    | 12 / 0.75       | 16            | 400 | normal   | `text-xs font-normal text-muted-foreground`                                           |
| Заголовок `EmptyState`                             | 24 / 1.5        | 32            | 600 | normal   | `text-2xl font-semibold`; наследует foreground поверхности                            |

Роли секции и вложенного блока задают выбор для нового текста. Строка `CardTitle` фиксирует базовый контракт примитива, а не рекомендует заголовок 16px: в новой композиции задавайте ему `text-lg leading-7` = 18/28px. Источники: [стили PageHeader](../../apps/web/shared/ui/page-header/styles.ts), [Card](../../packages/ui/src/components/card/card.tsx), [Dialog](../../packages/ui/src/components/dialog.tsx), [Label](../../packages/ui/src/components/label.tsx), [EmptyState](../../packages/ui/src/components/empty-state/empty-state.tsx). Остальные готовые примитивы сохраняют размеры по своей роли; это не повод уменьшать основной текст.

| Разрешённый вес | Класс           | Применение                                    |
| --------------- | --------------- | --------------------------------------------- |
| 400             | `font-normal`   | Основной текст, описание, метаданные          |
| 500             | `font-medium`   | Кнопки, подписи полей                         |
| 600             | `font-semibold` | Заголовки страниц, секций, карточек, диалогов |

Не добавляйте 700 и другие веса в рабочий экран без изменения общей нормы. На странице один `h1`, секции используют `h2`, вложенные разделы — `h3`. HTML-уровень передаёт структуру, класс — визуальную роль; `CardTitle` сам по себе не создаёт HTML-заголовок. Длинные заголовки переносятся; сокращение допустимо, если полное значение доступно при открытии или другим доступным способом.

## Шапка страницы и навигационный контекст

У рабочей страницы есть единая шапка: локальная навигация при необходимости, заголовок, краткое описание и действия. Используйте `PageHeader` из `@/shared/ui/page-header`: обязательные `title` и `description`, дополнительные `navigation`, `actions` и `className`. Навигация занимает строку над заголовком, действия располагаются справа и переносятся на узком экране. Глобальный header приложения со сворачиванием sidebar и пользовательским меню не заменяет шапку страницы.

Классы типографики находятся в `shared/ui/page-header/styles.ts`: `pageTitleClassName` и `pageDescriptionClassName`. Изменяйте общую типографику там. `PageHeader` не задаёт внешние отступы: их определяет страница.

- Заголовок называет текущий раздел или объект. Описание объясняет назначение экрана либо уточняет контекст команды и проекта.
- Для вложенного экрана оставляйте понятный переход к родителю. Используйте реальные route-хелперы из `shared/config`, сохраняйте идентификаторы команды и проекта.
- Главное действие располагайте рядом с шапкой. На узкой ширине группа действий переносится под текст; не уменьшайте заголовок ради кнопки.
- Поиск, фильтры и переключение представления размещайте после шапки, перед результатами. Действия строки остаются рядом со строкой.
- Активный пункт навигации должен соответствовать текущему разделу, включая вложенные URL. Пользователь должен понимать, к какому проекту относится открытый экран.

Не показывайте фиктивные breadcrumbs и ссылки без назначения. Если имя объекта ещё загружается, сохраняйте место под контекст; не выводите технический идентификатор вместо понятного названия без необходимости.

Минимальная композиция шапки в `apps/web`:

```tsx
import { PageHeader } from '@/shared/ui/page-header'

export function SettingsHeader() {
	return (
		<PageHeader
			title='Настройки'
			description='Параметры текущего рабочего пространства.'
			className='mb-6'
		/>
	)
}
```

Передавайте готовые ссылки в `navigation`, а кнопки с реальными обработчиками — в `actions`. Сам `PageHeader` не выполняет запросы и не определяет маршруты.

## Контейнеры, отступы и адаптивность

Базовый шаг Tailwind — `--spacing: 0.25rem` = 4px при корневых 16px. Число в `gap-6` — множитель шага, а не px. Для интервалов рабочего UI используйте следующую шкалу; размеры контролов задаются отдельно в таблице компонентов.

| Шаг | rem   | px  | Пример класса           | Применение                                      |
| --- | ----- | --- | ----------------------- | ----------------------------------------------- |
| 0   | 0     | 0   | `p-0`                   | Сброс отступа готовой композиции                |
| 1   | 0.25  | 4   | `gap-1`                 | Плотная группа `Button xs`                      |
| 1.5 | 0.375 | 6   | `mt-1.5`, `gap-1.5`     | Описание под H1, `Button sm`                    |
| 2   | 0.5   | 8   | `gap-2`                 | Иконка и подпись, группа действий               |
| 3   | 0.75  | 12  | `gap-3`, `px-3`         | Строки шапки, внутренние поля Input             |
| 4   | 1     | 16  | `gap-4`, `px-4`         | Группа полей, поля страницы до `sm`             |
| 5   | 1.25  | 20  | `py-5`, `mb-5`          | Вертикальные поля страницы, после toolbar       |
| 6   | 1.5   | 24  | `gap-6`, `mb-6`, `px-6` | После шапки, самостоятельные блоки, поля с `sm` |
| 8   | 2     | 32  | `p-8`                   | Просторное пустое состояние                     |

После шапки используйте `gap-6` родителя **или** `mb-6` шапки, не оба сразу. Внутри группы задавайте расстояние через `gap`, внешнее отделение блока — через margin или gap контейнера. Не вводите дополнительный шаг для локального визуального подбора.

| Область                                       | Размер                    | Классы / источник                 |
| --------------------------------------------- | ------------------------- | --------------------------------- |
| Обычная рабочая страница                      | max 960px / 60rem         | `mx-auto w-full max-w-[960px]`    |
| Широкая рабочая страница                      | max 1760px / 110rem       | `mx-auto w-full max-w-[1760px]`   |

| PageHeader: навигация, строка текста/действий | gap 12px                  | `gap-3`, с `sm` строка `flex-row` |
| PageHeader: группа действий                   | gap 8px                   | `gap-2`                           |
| Sidebar открытый / свёрнутый                  | 224px / 48px              | `w-56` / `w-12`                   |
| Глобальный header, верхняя строка sidebar     | высота 56px               | `h-14`; header `px-3` = 12px      |

Ширина контейнера не меняет H1 и ритм шапки. Общего обязательного `PageShell` нет: контейнер задаёт страница. Каркас из [Layout](../../apps/web/widgets/main-layout/ui/layout.tsx) занимает `h-screen`, основной контент прокручивается внутри `main` (`overflow-auto`). Размеры навигации заданы в [Sidebar](../../apps/web/widgets/main-layout/ui/sidebar/sidebar.tsx) и [Header](../../apps/web/widgets/main-layout/ui/header/header.tsx).

| Breakpoint   | rem | px при 16px  | Применение                                              |
| ------------ | --- | ------------ | ------------------------------------------------------- |
| без префикса | —   | любая ширина | Базовая вертикальная композиция                         |
| `sm`         | 40  | 640          | Строка PageHeader, поля 24px, desktop-композиция Dialog |
| `md`         | 48  | 768          | Desktop-sidebar; Input переходит на 14px                |
| `lg`         | 64  | 1024         | Дополнительное пространство для широких данных          |
| `xl`         | 80  | 1280         | Дополнительное пространство для широких данных          |
| `2xl`        | 96  | 1536         | Дополнительное пространство для широких данных          |

Breakpoint включает правила начиная с указанной ширины. Источник шкалы — установленный `tailwindcss/theme.css`, значения в приложении не переопределены. До `md` sidebar открывается через `Sheet`. На узкой ширине переносите действия и инструменты, добавляйте `min-w-0` flex-детям с длинным текстом. Горизонтальную прокрутку ограничивайте областью широких данных: `body` скрывает горизонтальное переполнение. Проверяйте доступ к действиям при свёрнутом sidebar и увеличении масштаба.

## Поверхности и иконки

### Радиусы

Источник — `globals.css`. Базовый radius и две прикладные роли не взаимозаменяемы. Значения вычислены при 1rem = 16px; формулы алиасов используют rem-базу и поправку в px.

| Токен / класс          | Значение или формула          | px  | Применение                                       |
| ---------------------- | ----------------------------- | --- | ------------------------------------------------ |
| `--radius`             | `0.375rem`                    | 6   | База алиасов                                     |
| `--radius-control`     | `8px`                         | 8   | Button, Input: `rounded-[var(--radius-control)]` |
| `--radius-surface`     | `10px`                        | 10  | Card, Dialog: `rounded-[var(--radius-surface)]`  |
| `rounded-sm`           | `var(--radius) - 4px`         | 2   | Компактные скругления                            |
| `rounded-md`           | `var(--radius) - 2px`         | 4   | Промежуточный алиас                              |
| `rounded-lg`           | `var(--radius)`               | 6   | Базовый алиас                                    |
| `rounded-xl`           | `var(--radius) + 4px`         | 10  | Алиас большого скругления                        |
| `rounded-2xl`          | `var(--radius) + 8px`         | 14  | EmptyState                                       |
| `rounded-3xl`          | `var(--radius) + 12px`        | 18  | Только если нужна отдельная крупная поверхность  |
| `rounded-4xl`          | `var(--radius) + 16px`        | 22  | Только если нужна отдельная крупная поверхность  |
| Кнопка закрытия Dialog | `var(--radius-control) - 2px` | 6   | Собственный контракт примитива                   |

Новый контрол использует control, новая карточка или диалог — surface. Не подменяйте эти роли ближайшим похожим алиасом и не создавайте произвольный radius для страницы.

### Границы, фокус и тени

| Элемент                             | Толщина / класс              | Цвет и поведение                                                                                         |
| ----------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------- |
| Card, Input, outline Button, Dialog | 1px, `border`                | `border-border` по базе; Input — `border-input`                                                          |
| Граница sidebar и header            | 1px, `border-r` / `border-b` | `border-sidebar-border`                                                                                  |
| Button / Input: клавиатурный фокус  | ring 3px                     | `focus-visible:border-ring focus-visible:ring-ring/50 focus-visible:ring-[3px]`                          |
| Button / Input: невалидное значение | граница 1px, цвет ring       | `aria-invalid:border-destructive aria-invalid:ring-destructive/20 dark:aria-invalid:ring-destructive/40` |
| Закрытие Dialog: фокус              | ring 2px + offset 2px        | `focus:ring-2 focus:ring-ring focus:ring-offset-2`                                                       |
| Базовый outline                     | цвет                         | `outline-ring/50`; примитивы задают собственный focus-visible                                            |

Цветовые формулы `/50`, `/20`, `/40` — доля непрозрачности токена, не отдельный оттенок палитры. Тени `--shadow-1/2/3` определены в `:root` и наследуются тёмной темой. Они доступны через `shadow-[var(--shadow-1)]` и аналогичные классы; это не алиасы `shadow-sm/lg`.

| Тень                                     | Где применяется / как выбирать                                                    |
| ---------------------------------------- | --------------------------------------------------------------------------------- |
| `shadow-xs`                              | Input, outline Button                                                             |
| `shadow-sm`                              | Card                                                                              |
| `shadow-lg`                              | Dialog                                                                            |
| `--shadow-1`, `--shadow-2`, `--shadow-3` | Общие переменные уровней; при новом общем оформлении выбирайте готовую переменную |

Точные значения из `globals.css` и установленного Tailwind:

```css
--shadow-1: 0 1px 2px 0 hsl(220 20% 20% / 0.06), 0 1px 1px -1px hsl(220 20% 20% / 0.05);
--shadow-2:
	0 8px 20px -12px hsl(220 30% 18% / 0.12), 0 3px 8px -4px hsl(220 20% 20% / 0.08);
--shadow-3:
	0 16px 36px -20px hsl(220 30% 18% / 0.18), 0 8px 18px -10px hsl(220 20% 20% / 0.12);
/* Tailwind theme.css */
--shadow-xs: 0 1px 2px 0 rgb(0 0 0 / 0.05);
--shadow-sm: 0 1px 3px 0 rgb(0 0 0 / 0.1), 0 1px 2px -1px rgb(0 0 0 / 0.1);
--shadow-lg: 0 10px 15px -3px rgb(0 0 0 / 0.1), 0 4px 6px -4px rgb(0 0 0 / 0.1);
```

Не переопределяйте готовую тень локально без потребности композиции. Новая общая тень требует изменения токена и этой спецификации.

## Применение компонентов

Сначала ищите компонент в `@repo/ui` и его story. Не копируйте Radix-разметку и базовые стили контрола в отдельную feature. Следующие таблицы описывают базовые компоненты без локальных `className`-переопределений.

### Button

Источник — [button.tsx](../../packages/ui/src/components/button.tsx). Для обычного действия используйте `default`, для плотной строки — `sm`, для особо компактного вспомогательного — `xs`, для крупного — `lg`. Это размеры видимого контрола, а не гарантия сенсорной области 44px.

| `size`    | Высота px / класс | Ширина         | Padding X px | Gap px | Текст px / line-height | Иконка px |
| --------- | ----------------- | -------------- | ------------ | ------ | ---------------------- | --------- |
| `default` | 36 / `h-9`        | по содержимому | 16, `px-4`   | 8      | 14 / 20                | 16        |
| `xs`      | 24 / `h-6`        | по содержимому | 8, `px-2`    | 4      | 12 / 16                | 12        |
| `sm`      | 32 / `h-8`        | по содержимому | 12, `px-3`   | 6      | 14 / 20                | 16        |
| `lg`      | 40 / `h-10`       | по содержимому | 24, `px-6`   | 8      | 14 / 20                | 16        |
| `icon`    | 36 / `size-9`     | 36px           | не задан     | 8      | 14 / 20                | 16        |
| `icon-xs` | 24 / `size-6`     | 24px           | не задан     | 8      | 14 / 20                | 12        |
| `icon-sm` | 32 / `size-8`     | 32px           | не задан     | 8      | 14 / 20                | 16        |
| `icon-lg` | 40 / `size-10`    | 40px           | не задан     | 8      | 14 / 20                | 16        |

У `default` дополнительно `py-2` = 8px; остальные варианты не задают вертикальный padding. Иконка получает указанный размер, если у неё нет собственного `size-*`. Радиус всех вариантов — control 8px, вес текста — 500.

| `variant` / назначение          | Базовые цвета                                       | Hover и особенности тёмной темы                                                                       |
| ------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `default`: главное действие     | `bg-primary text-primary-foreground`                | `hover:bg-primary/90`                                                                                 |
| `secondary`: вторичное          | `bg-secondary text-secondary-foreground`            | `hover:bg-secondary/80`                                                                               |
| `outline`: вторичное с контуром | `border bg-background shadow-xs`, текст наследуется | `hover:bg-accent hover:text-accent-foreground`; dark: `bg-input/30 border-input`, hover `bg-input/50` |
| `ghost`: вспомогательное        | Прозрачный фон, текст наследуется                   | `hover:bg-accent hover:text-accent-foreground`; dark hover `bg-accent/50`                             |
| `destructive`: опасное действие | `bg-destructive text-white`                         | `hover:bg-destructive/90`; dark `bg-destructive/60`; focus ring destructive 20%, dark 40%             |
| `link`: оформление перехода     | `text-primary underline-offset-4`                   | `hover:underline`                                                                                     |

Все варианты: `disabled:pointer-events-none disabled:opacity-50`. Focus-visible и aria-invalid приведены в таблице границ. Не придумывайте отдельные hover/active HEX; активный цвет в базовом Button отдельно не задан. Для перехода используйте ссылку; при оформлении кнопкой — `asChild`. Опасное действие с потерей данных требует подтверждения.

### Input и Dialog

Источники — [input.tsx](../../packages/ui/src/components/input.tsx) и [dialog.tsx](../../packages/ui/src/components/dialog.tsx).

| Компонент / область         | Размеры и отступы                                                                            | Цвет и оформление                                                                     |
| --------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Input                       | высота 36px `h-9`; ширина 100%; X 12px `px-3`, Y 4px `py-1`; radius 8px                      | `border-input`, `bg-transparent`; dark `bg-input/30`; `shadow-xs`                     |
| Input: текст                | 16/24px до `md`, 14/20px с `md`                                                              | `placeholder:text-muted-foreground`, selection `bg-primary text-primary-foreground`   |
| Input: disabled             | opacity 50%, события указателя отключены                                                     | `disabled:cursor-not-allowed`; фокус и ошибка как в таблице границ                    |
| DialogContent до `sm`       | ширина 100%, max `calc(100% - 2rem)` — по 16px до края; padding 24px `p-6`, gap 16px `gap-4` | `bg-background`, border 1px, radius 10px, `shadow-lg`, `z-50`                         |
| DialogContent с `sm`        | max 512px / 32rem, `sm:max-w-lg`                                                             | центрирование 50% + translate −50%; duration 200ms                                    |
| DialogHeader / DialogFooter | padding 16px `p-4`, gap 8px `gap-2`                                                          | Header: центр до `sm`, слева с `sm`; Footer: `flex-col-reverse`, с `sm` строка справа |
| Dialog: закрытие            | top/right 16px, иконка 16px, radius 6px                                                      | opacity 70%, hover 100%; focus 2px + offset 2px                                       |
| DialogOverlay               | `fixed inset-0 z-50`                                                                         | `bg-black/50`; fade при открытии/закрытии                                             |

У DialogContent и DialogHeader/Footer собственные padding: они складываются. Не добавляйте ещё один внешний отступ по привычке; для особой композиции явно переопределяйте нужный слой, сохраняя доступное название, закрытие и возврат фокуса. Dialog не задаёт max-height: в длинной форме отдельно ограничьте высоту и организуйте внутреннюю прокрутку.

У поля обязательна видимая связанная подпись. Placeholder даёт пример, ошибка объясняет исправление, связана с полем и сопровождается `aria-invalid`. Во время отправки предотвращайте повторное действие и показывайте состояние на кнопке.

Доменная композиция остаётся в `views` или `widgets`. В общий пакет выносите UI, применимый в нескольких контекстах и не зависящий от API фичи; общий вариант добавляйте вместе со story.

## Загрузка, пустой результат и ошибка

При загрузке сохраняйте шапку, навигацию и геометрию контента. Для карточек используйте `CardSkeleton`, для отдельных областей — `Skeleton`. Не показывайте сообщение «нет данных», пока запрос не завершён.

Пустое состояние объясняет причину и следующий шаг. Для первого заполнения предложите создание, для поиска без результатов — изменение запроса или сброс фильтров. Эти состояния имеют разные тексты.

При ошибке сохраняйте контекст и давайте повторить запрос, если это применимо. Локальная ошибка формы остаётся рядом с полем или формой; toast дополняет обратную связь, но не заменяет сообщение, по которому нужно действовать.

У `EmptyState` уровень заголовка по умолчанию — `h1`, для самостоятельного экрана. Под существующим `PageHeader` передавайте `headingLevel='h2'`, чтобы сохранить единственный `h1` страницы.

## Доступность и проверка изменения

Это требования к проектированию и ревью, а не заявление о сертификации всего интерфейса.

- Все действия доступны с клавиатуры; фокус видим и не скрывается под слоями. Сохраняйте focus-visible стили UI-kit.
- Ссылки выполняют переходы, кнопки — действия. Не заменяйте их кликабельным `div`.
- Диалог имеет название, понятное закрытие и возврат фокуса. Сохраняйте поведение готовых Radix-композиций.
- Проверяйте контраст текста и контролов в обеих темах, включая muted, disabled, hover и фокус. Один семантический токен не гарантирует контраст любой комбинации.
- Для touch-сценариев стремитесь к области нажатия не менее 44×44 CSS px: увеличивайте область вокруг компактной иконки и расстояние между соседними действиями. `size-11` соответствует 44px при стандартной шкале, `size-44` — 176px.
- При увеличении масштаба текст и действия остаются доступны. Анимация не должна мешать работе; учитывайте `prefers-reduced-motion`.

Для оценки используйте [критерий контраста WCAG](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) и [критерий минимальной области нажатия](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Ориентир 44×44px выше не означает, что все текущие контролы уже имеют такую область.

## Как добавить общий UI

Например, повторяющаяся панель действий может оборачивать существующие кнопки, сохраняя перенос на узком экране. Создайте `packages/ui/src/components/action-bar.tsx`:

```tsx
import type { ComponentProps } from 'react'

import { cn } from '@repo/ui/lib/utils'

export function ActionBar({ className, ...props }: ComponentProps<'div'>) {
	return <div className={cn('flex flex-wrap items-center gap-2', className)} {...props} />
}
```

Добавьте экспорт в `packages/ui/src/components/index.ts` и story рядом с компонентом. Покажите длинные подписи и перенос действий; проверьте светлую и тёмную темы. Если композиция нужна только одной странице, оставьте её рядом с этой страницей.

Из корня репозитория Storybook запускается без полного приложения:

```bash
pnpm storybook
```

Перед передачей UI проверьте шапку и описание, обычную и узкую ширину, обе темы, длинные данные, клавиатуру, loading/empty/error и недоступные действия. Storybook помогает изолировать компонент; контекст навигации и поведение контейнера проверяйте на странице приложения. Дополнение a11y сейчас настроено как `todo`, поэтому его наличие само по себе не подтверждает прохождение проверки доступности.
